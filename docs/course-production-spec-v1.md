# 课程制作规范 V1.0

本规范用于统一 Ruyi RISC-V Linux 课程的多人协作生产标准。后续课程文档、PPT 和实验指导书均以本规范为准。

## 目标

- 让多人分工写作时保持结构、深度、风格和交付物一致。
- 先定义标准，再批量生产课程内容。
- 保证课程“入门门槛低，出门能力高”。
- 本课程以 RISC-V Linux 开发板为目标平台，以 RuyiSDK 为统一工具入口，以 C 语言应用开发为主线，训练学生完成从环境搭建、交叉编译、外设控制到联网通信和综合项目交付的完整嵌入式开发流程。
- 先完成一个完整样章，再根据反馈扩展全书内容。

## 一节课标准结构

每个 Class 对应一个 `class*.md`、一套 PPT 和一份实验指导书。第一章按 5 个 Class 和 5 个 Lab 组织；后续章节扩展时继续保持“讲义、PPT、实验、代码材料”一一对应。

| 项目 | 标准 |
| --- | --- |
| 知识点数量 | 每个 Class 围绕 3-5 个核心知识点展开 |
| 课程文档 | 1 份 `class*.md` |
| PPT | 30-36 页左右 |
| 实验 | 每个 Class 对应 1 个 Lab，建议 30 分钟内完成 |
| 代码 | 只放必要示例和实验代码，避免大段无解释代码 |
| 图表 | 每个重点知识点至少 1 张图、流程图、结构图或运行截图 |
| 练习 | 每讲至少 1 个课堂练习或思考题 |
| 运行验证 | 必须有可观察结果 |

## 课程文档规范

每个 `class*.md` 必须包含：

1. 本讲目标
2. 前置条件
3. 知识简介
4. 环境准备
5. 操作步骤
6. 运行验证
7. 常见问题
8. 本讲成果

### 内容要求

| 项目 | 标准 |
| --- | --- |
| 目标 | 3 条左右，必须可验证 |
| 知识点 | 按后续补充的大纲组织 |
| 原理说明 | 每个重点知识点必须解释“为什么”和“怎么用” |
| 图表 | 每个重点知识点建议配图，图必须有编号和解释 |
| 代码 | 代码后必须有逐段说明和运行验证 |
| 练习 | 每讲至少 1 个练习或思考题 |
| 常见问题 | 至少 2 个，来自真实调试或可预见错误 |
| 成果 | 必须能对应 `docs/course-plan.md` 的运行验证 |

### 写作风格

- 面向本科或初学者，先讲使用场景，再讲操作步骤。
- 技术名词保留英文，第一次出现时解释含义。
- 命令、路径、函数名、文件名使用 Markdown 行内代码。
- 不整段搬运第三方资料；引用资料时标明来源。
- 不把扩展方向内容提前塞入主线章节。

## PPT 规范

每讲 PPT 建议 30-36 页，和课程文档一一对应。

| 页面类型 | 建议页数 | 内容 |
| --- | --- | --- |
| 封面与目标 | 2-3 页 | 标题、本讲目标、学习成果 |
| 知识点导入 | 1-2 页 | 本讲知识路线、前后讲衔接 |
| 知识点讲解 | 18-24 页 | 围绕本讲知识点展开 |
| 实验说明 | 3-5 页 | 实验目标、步骤、运行验证、提交要求 |
| 小结 | 2 页 | 本讲成果、常见错误、下一讲连接 |

### PPT 要求

- PPT 内容必须来自课程文档，不出现讲义中没有解释的概念。
- 每个重点、难点理论知识应配图表。
- 每个实践操作应配步骤、截图或代码片段。
- 单页避免大段文字。
- 图片必须框出关键区域并编号。
- 代码页只展示核心片段，完整代码放入 `code/` 目录。

## 实验指导书规范

每个 Class 必须对应 1 个 Lab，建议 30 分钟内完成。除综合实验外，若某章设置阶段实验，应并入该章最后一个 Lab 中，不单独新增章节。

每个实验必须包含：

1. 实验标题
2. 对应讲次
3. 实验目标
4. 对应知识点
5. 实验环境
6. 硬件连接或部署关系
7. 实验任务
8. 实验步骤
9. 运行验证
10. 验收记录
11. 常见问题
12. 提交要求

### 实验分类

| 类型 | 用途 | 要求 |
| --- | --- | --- |
| 演示实验 | 教师课堂演示 | 结果直观、步骤短 |
| 必做实验 | 学生必须完成 | 能独立复现，有明确验收 |
| 拓展实验 | 学有余力或课程设计 | 标注拓展，不阻塞主线 |

## 代码材料规范

课程代码、实验代码和课后题代码统一存放在 `code/` 目录。当前阶段不预设章节子目录，后续按实际项目建立独立代码目录。讲义和实验指导书只展示必要片段，完整工程或配套材料通过项目路径引用。

```text
code/
└── project-name/
```

最低要求：

- 代码材料按项目放入 `code/<project-name>/`。
- 每个项目目录应包含必要说明，至少能说明用途、运行方式和验证方式。
- 讲义、实验指导书和课后题引用代码时，必须写明对应项目路径。
- 如果某一讲没有真实代码材料，不需要为它制造空目录；文档中直接说明该讲以环境记录或操作验证为交付物。

## 开发板与环境规范

- 课程目标平台统一表述为 RISC-V Linux 开发板，避免把课程写成单一板卡说明书。
- 第一章样章可使用 LicheePi 4A + RevyOS 作为示例环境；具体镜像、账号、串口、烧录方式和板级差异放入 `boards/` 作为参考资料。
- 主线工具入口为 RuyiSDK；工具链、交叉编译、调试和部署方式应围绕 RuyiSDK 与 RISC-V Linux 应用开发展开。
- QEMU 仅作为低硬件依赖内容的辅助说明，不作为实验验收环境。
- 当前阶段不同时展开多板路线；如后续支持多板，只能作为附录或拓展适配，不影响主线课程。
- 样章、实验和截图必须标注实际验证环境；截图和课程图片放入对应章节的 `assets/` 目录。

## 成长曲线要求

课程必须体现能力递进：

| 阶段 | 学生能力 |
| --- | --- |
| 认知 | 能说明 RISC-V 软件生态、课程目标平台和环境边界 |
| 工具 | 能安装 `ruyi`，完成版本检查和工具链查询 |
| 系统 | 能烧录 RevyOS，完成首次启动、登录和网络检查 |
| 连接 | 能建立串口、SSH 和 SCP 开发通道 |
| 判断 | 能判断目标设备是否适合使用 `ruyi device provision` |

不允许出现只有概念介绍、没有可验证操作结果的课程设计。

## 样章生产要求

在批量编写前，先完成：

- 1 个完整样章
- 1 套 PPT
- 1 套实验指导书

样章完成后，根据实际产出修正计划和模板。
