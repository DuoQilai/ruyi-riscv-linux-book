# 课程制作规范 V1.0

本规范用于统一 Ruyi RISC-V Linux 课程的多人协作生产标准。后续课程文档、PPT、实验指导书、代码工程和试讲材料均以本规范为准。

## 目标

- 让多人分工写作时保持结构、深度、风格和交付物一致。
- 先定义标准，再批量生产课程内容。
- 保证课程“入门门槛低，出门能力高”。
- 以 LicheePi 4A + RevyOS 为课程目标平台，外设、传感器、网络服务、RVV 和边缘智能演示均围绕该平台验证。
- 先完成一个完整样章，再根据反馈扩展全书内容。

## 一节课标准结构

每讲对应一个 `class*.md`、一套 PPT 和一份实验或项目指导书。每讲按 `docs/course-outline.md` 覆盖 6 个知识点，授课材料可根据课堂节奏把 6 个知识点组织为 3-4 个教学段落。

| 项目 | 标准 |
| --- | --- |
| 知识点数量 | 6 个，对应课程大纲；PPT 可合并为 3-4 个教学段落 |
| 课程文档 | 1 份 `class*.md` |
| PPT | 30-36 页左右 |
| 实验 | 1-3 个，单个实验建议 30 分钟以内；第 2、4、6 章末可使用综合项目 |
| 代码 | 只放必要示例和实验代码，避免大段无解释代码 |
| 图表 | 每个重点知识点至少 1 张图、流程图、结构图或运行截图 |
| 练习 | 每讲至少 1 个课堂练习或思考题 |
| 运行验证 | 必须有可观察结果 |

## 课程文档规范

每个 `class*.md` 必须包含：

1. 本讲目标
2. 前置条件
3. 知识简介
4. 环境准备
5. 操作步骤
6. 运行验证
7. 常见问题
8. 本讲成果

### 内容要求

| 项目 | 标准 |
| --- | --- |
| 目标 | 3 条左右，必须可验证 |
| 知识点 | 覆盖大纲中的 6 个知识点，可按主题合并讲解 |
| 原理说明 | 每个重点知识点必须解释“为什么”和“怎么用” |
| 图表 | 每个重点知识点建议配图，图必须有编号和解释 |
| 代码 | 代码后必须有逐段说明和运行验证 |
| 练习 | 每讲至少 1 个练习或思考题 |
| 常见问题 | 至少 2 个，来自真实调试或可预见错误 |
| 成果 | 必须能对应 `docs/course-plan.md` 的运行验证 |

### 写作风格

- 面向本科或初学者，先讲使用场景，再讲操作步骤。
- 技术名词保留英文，第一次出现时解释含义。
- 命令、路径、函数名、文件名使用 Markdown 行内代码。
- 不整段搬运第三方资料；引用资料时标明来源。
- 不把扩展方向内容提前塞入主线章节。

## PPT 规范

每讲 PPT 建议 30-36 页，和课程文档一一对应。

| 页面类型 | 建议页数 | 内容 |
| --- | --- | --- |
| 封面与目标 | 2-3 页 | 标题、本讲目标、学习成果 |
| 知识点导入 | 1-2 页 | 本讲 6 个知识点路线、前后讲衔接 |
| 知识点讲解 | 18-24 页 | 围绕 6 个知识点展开，可合并为 3-4 个教学段落 |
| 实验说明 | 3-5 页 | 实验目标、步骤、运行验证、提交要求 |
| 小结 | 2 页 | 本讲成果、常见错误、下一讲连接 |

### PPT 要求

- PPT 内容必须来自课程文档，不出现讲义中没有解释的概念。
- 每个重点、难点理论知识应配图表。
- 每个实践操作应配步骤、截图或代码片段。
- 单页避免大段文字。
- 图片必须框出关键区域并编号。
- 代码页只展示核心片段，完整代码放仓库。

## 实验指导书规范

每讲建议 1-3 个实验，单个实验控制在 30 分钟以内。第 2 章、第 4 章和第 6 章的章末实验可以按阶段综合项目组织。

每个实验必须包含：

1. 实验标题
2. 对应讲次
3. 实验目标
4. 对应知识点
5. 实验环境
6. 硬件连接或部署关系
7. 实验任务
8. 实验步骤
9. 运行验证
10. 验收记录
11. 常见问题
12. 提交要求

### 实验分类

| 类型 | 用途 | 要求 |
| --- | --- | --- |
| 演示实验 | 教师课堂演示 | 结果直观、步骤短 |
| 必做实验 | 学生必须完成 | 能独立复现，有明确验收 |
| 拓展实验 | 学有余力或课程设计 | 标注拓展，不阻塞主线 |

## 代码工程规范

每个需要代码的实验应尽量遵循统一结构：

```text
project/
├── README.md
├── Makefile
├── src/
├── include/
├── config/
├── data/
└── logs/
```

最低要求：

- 有 `README.md` 说明构建、运行和验证。
- 有统一构建入口，例如 `make build`。
- 有清理入口，例如 `make clean`。
- 代码注释说明关键逻辑，不写无意义注释。
- 运行结果必须能对应实验指导书的运行验证。
- 自动化脚本如需保留，优先放在项目外部的内部工程目录；公开仓库中的代码工程不强制包含 `scripts/`。

## 开发板与环境规范

- 课程目标板：LicheePi 4A（TH1520，RISC-V 64 位，4 x C910）。
- 目标系统：RevyOS。
- 主线工具链：RuyiSDK、RISC-V GNU Toolchain、Makefile/CMake、gdb/gdbserver。
- 外设主线：面包板、LED、按键、继电器或 MOSFET、风扇模块、光敏/电位器、DHT22、OLED、USB 摄像头。
- QEMU 仅作为低硬件依赖内容的辅助说明，不作为实验验收环境。
- 不同时展开其他多板路线；如后续支持多板，只能作为附录或拓展适配，不影响 LicheePi 4A + RevyOS 主线。
- 样章、实验和截图必须标注实际验证环境；板级差异记录到对应 `boards/` 子目录。

## 成长曲线要求

课程必须体现能力递进：

| 阶段 | 学生能力 |
| --- | --- |
| 入门 | 能烧录并进入 RevyOS，编译、部署和调试 C 程序 |
| 基础 | 能使用 GPIO、UART、PWM、ADC、I2C/SPI、OLED 和 DHT22 |
| 应用 | 能封装库，编写进程、IPC、多线程、文件、配置和日志程序 |
| 项目 | 能完成温控风扇和手机 MQTT 远程灯光控制 |
| 进阶 | 能完成 RVV 加速实验和边缘智能演示 |

不允许出现“第一章会点灯，最后一章还是只会点灯”的课程设计。

## 样章生产要求

在批量编写前，先完成：

- 1 个完整样章
- 1 套 PPT
- 1 套实验指导书
- 1 套可运行代码

样章完成后，根据实际产出修正计划和模板。
