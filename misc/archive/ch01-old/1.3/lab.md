# 实验 1.3 判断 ruyi device provision 的适用范围

| 项目 | 内容 |

## 实验目标

- 查询当前 `ruyi` 版本提供的 device/provision 能力。
- 根据精确设备标识判断课程目标板是否受支持。
- 对比手工烧录流程（实验 1.2）与自动化 provision 的差异。
- 在不冒险写入未知设备的前提下形成自动或手工流程决策。

## 实验任务

### 任务 1：检查命令能力

确认本机版本是否具有 device/provision 相关子命令。

### 任务 2：查询课程目标板支持

使用精确设备名称和变体查询，保存原始结果。

### 任务 3：对比手工与自动化路径

结合实验 1.2 的经验，从控制粒度、适用条件、误操作风险、可调试性和重复效率五个维度对比手工烧录与 provision。

### 任务 4：完成风险评估与路径选择

选择自动 provision、部分使用工具能力或完全手工烧录，并说明理由。

## 实验步骤

1. 记录版本和帮助：

```bash
ruyi --version
ruyi device --help
ruyi device provision --help
```

2. 根据帮助执行设备列表或搜索命令，查询 LicheePi 4A 及对应变体。
3. 填写手工 vs 自动化对比表：

| 维度 | 手工流程（实验 1.2） | 自动化 provision | 本课程选择 |
| --- | --- | --- | --- |
| 控制粒度 | 每步可控 | 流程封装 |  |
| 适用条件 | 有镜像即可 | 设备需在软件源中 |  |
| 误操作风险 | 人为确认每步 | 自动化可能跳过确认 |  |
| 可调试性 | 高 | 低 |  |
| 重复效率 | 低 | 高 |  |

4. 填写风险清单：

| 检查项 | 结论 | 依据 |
| --- | --- | --- |
| 设备是否明确列出 |  |  |
| 变体是否与实物一致 |  |  |
| 镜像是否匹配 |  |  |
| 写入目标是否唯一 |  |  |
| 数据是否已备份 |  |  |
| 是否具备恢复通道 |  |  |

5. 形成决策：

- 六项均明确且工具支持完整：可按帮助执行。
- 设备未列出或变体不明：停止自动写入，采用 1.2 手工流程。
- 工具只支持查询或下载：只使用已确认的非写入能力。

6. 若课程要求并确认安全后执行 provision，保存全部日志；否则只提交决策记录，不为"完成实验"而强行写入。
7. 对实际执行结果使用以下命令验证：

```bash
cat /etc/os-release
uname -m
ip -br addr
```

## 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 没有 `device` 子命令 | 当前版本不支持或命令结构变化 | 保存版本和帮助，结论为"当前版本不支持"，回退到 1.2 手工流程 |
| 搜不到设备 | 软件源未更新或设备未受支持 | 更新元数据后复查，仍无结果则走手工流程 |
| 设备名称相似 | 只按商品名判断 | 核对硬件版本、内存和存储变体 |
| 无法确认写入目标 | 多个存储设备同时连接 | 停止操作并断开无关设备 |
| 不知该选哪条路径 | 只看"能不能"而不看"该不该" | 先填风险清单和对比表，按证据选择 |
