# 1.1 RISC-V 平台认知与 ruyi 开发环境安装

## 本讲目标

- 能区分 RISC-V ISA、处理器核、SoC、开发板、操作系统和开发工具链。
- 能识别 LicheePi 4A 的主要接口，并说明它们在课程实验中的用途。
- 能形成个人课程环境清单，确认缺少的硬件、线缆和主机软件。
- 能说明 `ruyi` 在 RISC-V 开发环境中的作用，并完成安装与版本检查。
- 能更新软件源、查询可用工具链，并记录所选工具链的信息。
- 能使用编译器版本、目标三元组和简单编译结果验证工具链。

## 前置条件

- 具备基本计算机组成和 Linux 使用经验。
- 准备一台可联网的主机，建议使用 Linux x86_64。
- 准备 LicheePi 4A、稳定电源、USB 数据线、USB-TTL 串口模块和网络连接条件。

## 知识简介

### 平台分层：从 ISA 到应用

RISC-V 是开放指令集架构（Instruction Set Architecture，ISA），不是某一款芯片或开发板。课程使用的 LicheePi 4A 是搭载 TH1520 SoC 的开发板，RevyOS 是运行在开发板上的 Linux 发行版，`ruyi` 与 RISC-V GNU Toolchain 则属于开发工具。先建立这些层次，后续遇到"镜像不支持板卡""工具链架构不匹配"等问题时，才能准确定位故障所在。

图 1-1：课程平台分层

```text
RISC-V ISA
    ↓
处理器核 / SoC（TH1520）
    ↓
开发板（LicheePi 4A）
    ↓
操作系统（RevyOS）
    ↓
开发工具（ruyi、编译器、SSH、串口工具）
    ↓
课程应用与实验
```

### ruyi 与工具链

`ruyi` 是 RuyiSDK 提供的包管理与环境管理入口，用于发现和获取 RISC-V 开发所需的软件包、工具链及部分设备支持信息。它不等同于编译器：`ruyi` 负责管理，真正完成编译的是所安装的 GCC 或其他工具链。

图 1-2：ruyi 与编译工具链关系

```text
ruyi 命令
  ├─ 软件源与包信息
  ├─ 工具链获取
  ├─ 环境或配置管理
  └─ 设备支持查询
            ↓
      GCC / binutils / sysroot
            ↓
        目标程序
```

## 操作步骤

### 步骤 1：记录主机环境

```bash
uname -a
uname -m
```

`uname -m` 用于确认主机架构。主机架构与目标板架构可以不同，这正是后续需要工具链管理和交叉开发流程的原因。

### 步骤 2：识别课程平台层次

填写以下对应关系：

| 层次 | 本课程对象 |
| --- | --- |
| ISA | RISC-V 64 位 |
| SoC | TH1520 |
| 开发板 | LicheePi 4A |
| 操作系统 | RevyOS |
| 工具入口 | `ruyi`、GNU Toolchain、SSH/SCP、串口终端 |

### 步骤 3：检查开发板接口

重点识别供电接口、烧录或数据接口、串口调试口、网口、USB、HDMI、启动介质和扩展接口。记录接口名称，不凭外观猜测供电能力或电平。

### 步骤 4：建立个人环境清单

为每项标记"已有、缺少、待确认"，并记录型号。尤其确认 USB 线是否支持数据、USB-TTL 是否为 3.3 V 逻辑电平、主机是否有可用网络接口。

### 步骤 5：安装 ruyi 并确认命令位置

按照课程指定的 RuyiSDK 官方安装方式获取 `ruyi`，不要从来源不明的压缩包复制可执行文件。安装后执行：

```bash
command -v ruyi
ruyi --version
```

第一条命令确认 shell 实际调用的文件，第二条记录版本。若刚修改 `PATH`，可重新打开终端或执行 `hash -r`。

### 步骤 6：查看帮助与子命令

```bash
ruyi --help
```

帮助输出是当前安装版本最可靠的命令入口。课程中的后续命令应以本机帮助信息为准，避免把其他版本的参数直接照搬。

### 步骤 7：更新软件源并查询工具链

使用当前版本帮助中提供的软件源更新和包查询命令，搜索关键词 `toolchain`、`gcc` 或 `riscv`。记录候选包名称、版本、目标架构和 ABI。

```bash
ruyi --help
# 根据帮助信息执行软件源更新与包搜索
```

### 步骤 8：安装课程选定工具链

根据课程平台选择面向 RISC-V Linux 用户态的工具链。安装前确认它不是面向裸机环境的 `unknown-elf` 工具链；两者使用场景不同。

### 步骤 9：验证编译器

进入工具链环境后执行实际编译器命令：

```bash
<compiler> --version
<compiler> -dumpmachine
```

`-dumpmachine` 应显示 RISC-V 目标三元组。再编译最小程序：

```c
int main(void) { return 0; }
```

使用 `file` 检查输出文件的架构，暂不要求在主机直接运行 RISC-V 二进制。

## 课堂练习

1. 解释"LicheePi 4A 是 RISC-V"这句话为什么不够准确，并用 ISA、SoC、开发板三个术语重新表述。
2. 比较包含 `linux-gnu` 与包含 `unknown-elf` 的两个目标三元组，说明它们分别更适合 Linux 应用还是裸机程序。

## 常见问题

### 把 RISC-V 当成操作系统

RISC-V 定义处理器执行指令的接口；RevyOS 才是本课程使用的操作系统。两者位于不同层次。

### 把所有 USB-C 线都当成数据线

部分线缆只能供电。无法识别设备时，应先更换已确认支持数据传输的线缆。

### 未确认串口电平

课程调试串口通常使用 3.3 V TTL。错误连接 5 V 电平可能损坏设备，接线前必须核对板卡资料。

### `ruyi: command not found`

通常是安装目录未加入 `PATH`，或 shell 尚未重新加载配置。先用绝对路径执行，再检查 shell 配置文件。

### 软件源更新失败

检查 DNS、代理、系统时间和证书。不要在网络失败时反复删除本地配置，应先保存错误输出。

### 工具链安装后仍调用系统 GCC

使用 `command -v <compiler>` 和 `<compiler> -dumpmachine` 确认路径与目标，避免只看命令名称。
