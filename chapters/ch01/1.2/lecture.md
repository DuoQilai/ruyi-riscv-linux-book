# 1.2 安装 ruyi 并检查工具链

## 本讲目标

- 能说明 `ruyi` 在 RISC-V 开发环境中的作用，并完成安装与版本检查。
- 能更新软件源、查询可用工具链，并记录所选工具链的信息。
- 能使用编译器版本、目标三元组和简单编译结果验证工具链。

## 前置条件

- 已完成 1.1 的主机环境检查。
- 主机能够访问课程指定的软件源。
- 具备执行命令、修改 `PATH` 和查看文件权限的基础能力。

## 知识简介

`ruyi` 是 RuyiSDK 提供的包管理与环境管理入口，用于发现和获取 RISC-V 开发所需的软件包、工具链及部分设备支持信息。它不等同于编译器：`ruyi` 负责管理，真正完成编译的是所安装的 GCC 或其他工具链。安装时需要同时关注程序本身、软件源元数据和命令搜索路径。

图 1-2 建议展示：

```text
ruyi 命令
  ├─ 软件源与包信息
  ├─ 工具链获取
  ├─ 环境或配置管理
  └─ 设备支持查询
            ↓
      GCC / binutils / sysroot
            ↓
        目标程序
```

## 环境准备

| 项目 | 要求 | 检查方式 |
| --- | --- | --- |
| 主机 | 课程支持的 Linux 主机环境 | `uname -m` |
| 网络 | 可访问 RuyiSDK 软件源 | 使用浏览器或课程提供的连通性检查 |
| 基础工具 | `curl` 或 `wget`、文件校验工具 | `command -v curl` |
| 安装权限 | 用户目录可写 | `test -w "$HOME"` |

## 操作步骤

### 步骤 1：安装并确认命令位置

按照课程指定的 RuyiSDK 官方安装方式获取 `ruyi`，不要从来源不明的压缩包复制可执行文件。安装后执行：

```bash
command -v ruyi
ruyi --version
```

第一条命令确认 shell 实际调用的文件，第二条记录版本。若刚修改 `PATH`，可重新打开终端或执行 `hash -r`。

### 步骤 2：查看帮助与子命令

```bash
ruyi --help
```

帮助输出是当前安装版本最可靠的命令入口。课程中的后续命令应以本机帮助信息为准，避免把其他版本的参数直接照搬。

### 步骤 3：更新软件源并查询工具链

使用当前版本帮助中提供的软件源更新和包查询命令，搜索关键词 `toolchain`、`gcc` 或 `riscv`。记录候选包名称、版本、目标架构和 ABI。

```bash
ruyi --help
# 根据帮助信息执行软件源更新与包搜索
```

### 步骤 4：安装课程选定工具链

根据课程平台选择面向 RISC-V Linux 用户态的工具链。安装前确认它不是面向裸机环境的 `unknown-elf` 工具链；两者使用场景不同。

### 步骤 5：验证编译器

进入工具链环境后执行实际编译器命令：

```bash
<compiler> --version
<compiler> -dumpmachine
```

`-dumpmachine` 应显示 RISC-V 目标三元组。再编译最小程序：

```c
int main(void) { return 0; }
```

使用 `file` 检查输出文件的架构，暂不要求在主机直接运行 RISC-V 二进制。

## 课堂练习

比较包含 `linux-gnu` 与包含 `unknown-elf` 的两个目标三元组，说明它们分别更适合 Linux 应用还是裸机程序。

## 常见问题

### `ruyi: command not found`

通常是安装目录未加入 `PATH`，或 shell 尚未重新加载配置。先用绝对路径执行，再检查 shell 配置文件。

### 软件源更新失败

检查 DNS、代理、系统时间和证书。不要在网络失败时反复删除本地配置，应先保存错误输出。

### 工具链安装后仍调用系统 GCC

使用 `command -v <compiler>` 和 `<compiler> -dumpmachine` 确认路径与目标，避免只看命令名称。
