# 1.2 镜像烧录、首次启动与开发通道建立

## 本讲目标

- 能说明镜像、启动介质、引导程序和根文件系统之间的关系。
- 能在确认板卡型号、镜像版本和目标介质后完成安全烧录。
- 能在首次启动后检查用户、网络、时间和 apt 软件源状态。
- 能说明串口登录与 SSH 登录的差异，并为故障排查选择合适通道。
- 能完成 SSH 首次连接、主机指纹核对和密钥登录配置。
- 能使用 SCP 在主机与开发板之间双向传输文件并校验内容。

## 前置条件

- 已完成 1.1 的主机环境检查与 ruyi 工具链安装。
- 已确认开发板型号和供电要求。
- 已准备课程指定的 RevyOS 镜像及其发布说明。
- 已准备可靠数据线、启动介质和 3.3 V USB-TTL 串口模块。

## 知识简介

### 镜像烧录与首次启动

镜像烧录不是简单的"复制文件"。烧录工具会把引导程序、内核、设备树和根文件系统写入指定介质或分区。错误选择设备可能覆盖主机磁盘，错误选择板卡镜像则可能导致无法启动。课程要求先记录镜像来源与校验值，再识别目标设备，最后执行与该镜像发布说明一致的烧录流程。

图 1-3：镜像烧录与启动流程

```text
镜像发布包
  ├─ 引导程序
  ├─ Linux 内核与设备树
  └─ RevyOS 根文件系统
          ↓ 烧录
   eMMC / SD / 其他启动介质
          ↓ 上电启动
      串口日志 / 登录界面
```

### 串口、SSH 与 SCP 开发通道

串口是直接连接开发板的本地调试通道，不依赖网络，适合观察启动日志和修复网络配置。SSH（Secure Shell）通过网络提供加密远程终端，适合日常开发。SCP（Secure Copy）复用 SSH 连接传输文件。稳定课程环境应同时保留串口备用通道和 SSH 主工作通道。

图 1-4：主机与开发板连接通道

```text
主机
 ├─ USB-TTL ── 串口 ──> 启动日志与本地 shell
 └─ Ethernet/Wi-Fi ── SSH ──> 远程 shell
                       └─ SCP ──> 文件传输
```

## 环境准备

| 项目 | 要求 | 检查方式 |
| --- | --- | --- |
| 镜像 | 与 LicheePi 4A 匹配的课程指定 RevyOS 镜像 | 核对发布页、文件名和日期 |
| 校验工具 | `sha256sum` 或等效工具 | `sha256sum --version` |
| 烧录工具 | 与镜像说明匹配的工具 | 查看工具版本 |
| 观察通道 | 串口优先，也可使用 HDMI | 确认连接可用 |
| 供电 | 满足板卡要求的稳定电源 | 核对适配器规格 |
| SSH 客户端 | 主机具备 `ssh`、`scp` | `ssh -V` |
| SSH 服务 | 板端服务已安装并运行 | `systemctl status ssh` |
| 串口 | 3.3 V USB-TTL 与终端程序 | 检查设备节点 |

## 操作步骤

### 步骤 1：记录并校验镜像

```bash
sha256sum <image-file>
```

将计算结果与发布方提供的校验值比对。校验不一致时停止烧录，重新下载。

### 步骤 2：识别目标设备

按镜像说明让开发板进入对应烧录模式，再使用烧录工具的设备列表命令确认设备。一次只连接一块待烧录板，降低误操作概率。

### 步骤 3：执行烧录

严格使用该镜像版本的发布说明。不要把其他板卡、其他年份或其他存储介质的命令拼接使用。保存完整日志，等待工具明确报告成功后再断电。

### 步骤 4：观察首次启动

接通串口或显示器后启动开发板。首次启动可能进行文件系统扩展、密钥生成或初始化，耗时可能长于后续启动。不要因短暂无输出立即断电。

### 步骤 5：检查系统与账户

```bash
cat /etc/os-release
uname -a
uname -m
id
hostnamectl
```

确认系统为课程指定 RevyOS，架构为 `riscv64`，并记录当前用户与主机名。

### 步骤 6：检查网络、时间和软件源

```bash
ip -br addr
ip route
timedatectl
grep -R --no-filename -h '^deb ' /etc/apt/sources.list /etc/apt/sources.list.d 2>/dev/null
sudo apt update
```

先检查链路、地址、路由和时间，再执行 `apt update`。软件源失败不等于需要立即换源，应根据错误区分 DNS、时间、网络或仓库问题。

### 步骤 7：建立串口连接

断电接线，连接 `GND-GND`、主机模块 `TX` 到板端 `RX`、主机模块 `RX` 到板端 `TX`，不要连接 5 V 电源脚。打开终端工具并设置板卡资料指定的波特率。

### 步骤 8：配置 SSH 登录

检查板端 SSH 服务与地址：

```bash
ip -br addr
sudo systemctl enable --now ssh
sudo systemctl status ssh --no-pager
```

首次 SSH 登录：

```bash
ssh <user>@<board-ip>
```

首次连接会显示主机指纹。应通过串口或受信任渠道核对，而不是习惯性输入 `yes`。登录后执行 `hostname` 和 `uname -m`，确认进入的是目标板。

### 步骤 9：配置密钥登录

```bash
ssh-keygen -t ed25519 -C "riscv-course"
ssh-copy-id <user>@<board-ip>
ssh <user>@<board-ip> 'hostname; uname -m'
```

私钥留在主机，不能复制给他人。公钥写入板端用户的 `~/.ssh/authorized_keys`。

### 步骤 10：SCP 双向传输并校验

```bash
printf 'RISC-V course transfer test\n' > transfer-test.txt
sha256sum transfer-test.txt
scp transfer-test.txt <user>@<board-ip>:/tmp/
ssh <user>@<board-ip> 'sha256sum /tmp/transfer-test.txt'
scp <user>@<board-ip>:/etc/os-release ./board-os-release.txt
```

主机和板端哈希一致，说明文件内容未变化。

## 常见问题

### 烧录工具找不到设备

检查是否进入正确模式、数据线是否可传输、主机权限和 USB 端口是否正常。

### 启动后无画面

无画面不一定代表未启动。优先使用串口查看引导日志，并检查供电和镜像是否匹配。

### `apt update` 报证书或 Release 时间错误

先检查系统时间。时间严重错误时，TLS 证书和仓库元数据校验都会失败。

### SSH 连接超时

通常是 IP、路由、网段或防火墙问题。先在串口中检查 `ip addr`、`ip route` 和 SSH 服务状态。

### 主机指纹发生变化

可能是开发板重装系统，也可能连接了另一台设备。先核对 IP 和串口中的主机指纹，再清理旧记录。

### SCP 提示权限不足

先传到用户有写权限的目录，如用户家目录或 `/tmp`，再在板端使用受控权限移动文件。

### 串口乱码

波特率错误或线路不稳。按板卡资料重新设置并检查接线。
