本章实验 · 继电器控制风扇

GPIO 输出：继电器直连 · 假温度阈值 · 荔枝派 4A

这节课要做成什么样

用一句话：程序里一段「假温度」来回变化；超过上限，继电器吸合、风扇转；低于下限，继电器释放、风扇停。第三章不读任何传感器——它只教你一件事：怎么用一根 GPIO 脚输出高/低，去驱动执行器。

你不需要先成为电子工程师。本页按「认零件 → 认排针 → 一根根接线 → 编译运行 → 看现象」写。真传感器（DHT22）第四章再接。

成功时你能演示：终端周期性打印假温度；温度升过上限出现 [INFO] fan ON，风扇真转；温度降下来 fan OFF，风扇停。
安全：风扇的大电流不要直接接在板子的「信号脚」上——必须经过继电器。板子上标着 Fan Power 的白色插座是板载散热风扇用的，跟本实验风扇无关，别插错。接线时尽量断电操作。

桌上要摆什么

东西它干什么（人话）
荔枝派 4A跑 Linux 的小电脑；排针用来接线
继电器模块（1 路，5V）小信号扳动的「自动开关」，去通断风扇电源
5V 小风扇被继电器开关的负载；红线正极、黑线负极
面包板 + 杜邦线把各个模块连起来

没有 DHT22、没有电平转换板、没有额外的降压板——第三章就这几样。

整体数据流

程序内部假温度 T（24 ↔ 31°C 循环）
              │
              ▼
       阈值判断（滞回）
   T > 28 → 开；T < 26 → 关；中间保持
              │
              ▼
       GPIO 输出 高/低（IO1_5）
              │
              ▼
       继电器 吸合 / 释放
              │  通断 5V 电源
              ▼
        5V 风扇 转 / 停

整条链：决策（阈值）→ 执行（GPIO → 继电器 → 风扇）。传感器那一段留到第四章。

荔枝派排针怎么认

板子侧面那排竖针，叫 20 针排针（两排，每排 10 根）。本课只用其中几根。

关键事实：这些信号脚的高电平约 1.8V（不是常见的 3.3V）。本课继电器是光耦隔离的，1.8V 直连就能触发——不用电平转换。

排针上的字本课用途
5V给继电器线圈供电；给风扇供电（经继电器）
GND地线；所有模块的地都连到这里（共地）
IO1_5本课默认：继电器/风扇信号脚
IO1_6备用（第四章接 DHT22）
插针方位图见仓库 chapters/ch03/manuals/lpi4a-wiki-assets/io_map.png。以文档图为准；早期板丝印可能不准。

程序里怎么对应：本课板子（RevyOS）上排针 GPIO 在 gpiochip5，其中 line 5 对应丝印 IO1_5。代码宏已经写好；若你的板子编号不同，按讲义「认脚要认丝印、编号要查运行时」一节现查现改。

接线总表（照抄）

先认清每块板子上的丝印文字（印在绿/黑板上的字母），再接线。丝印若和表不完全一致，以实物丝印为准，逻辑按下表「角色」对应。

A. 继电器（信号 + 供电）

从到说明
排针 IO1_5继电器信号脚 IN / X1GPIO 直连，不经过任何转换板
排针 5V继电器 V+ / VCC继电器线圈要 5V
排针 GND继电器 V- / GND共地，必接

继电器上的跳线帽拨到 H（高电平有效）：程序写「开」时给高，继电器吸合。

B. 风扇（走继电器触点，大电流不进 GPIO）

接法说明
排针 5V → 继电器 NO（常开）平时断开
继电器 COM（公共）→ 风扇红线继电器吸合后红线才有电
风扇黑线 → 排针 GND负极回地
排针 5V ──► [继电器 NO]──(吸合时接通)──[COM]──► 风扇红线
排针 GND ──────────────────────────────────────► 风扇黑线
排针 IO1_5 ──► 继电器 IN / X1（直连）
排针 5V  ──► 继电器 V+      排针 GND ──► 继电器 V-

步骤 1：接线

  1. 板子断电（拔电源更安心）。
  2. 按上一节总表接：先接 GND（共地），再接 5V，再接信号线 IO1_5 → IN，最后接风扇。
  3. 确认继电器跳线帽在 H。
  4. 确认没碰到 Fan Power 白色插座。
  5. 再上电。

本步成功判据：继电器模块电源指示灯亮；未触发时风扇不转；你能指着线说出「这根是地 / 这根是信号」。

步骤 2：编译运行

程序在 chapters/ch03/code/temperature-fan/。它申请 IO1_5 为输出，用假温度跑阈值判断。板端原生编译最省事：

$ ssh user@board-ip 'cd ~/ruyi-riscv-embedded/ch03-lab && make && sudo ./temperature_fan'

把 user@board-ip 换成你第一章能登录的账号和地址。若代码还没拷到板子，先按第一章的 SCP 传过去。

为什么 sudo？/dev/gpiochip* 默认归 root，普通用户打不开。也可以用第一章教的主机交叉编译 + scp 的方式。

步骤 3：假温度验收

预期：

  • 启动打印 fake temperature: T_HIGH=28.0 T_LOW=26.0，并说明继电器在 IO1_5。
  • 周期性打印 [INFO] temp=…C fan=OFF|ON，假温度在 24~31 之间来回。
  • 升过 28°C → [INFO] fan ON，继电器吸合（常有「咔」一声或工作灯亮），风扇转。
  • 降到 26°C 以下 → [INFO] fan OFF，风扇停。
  • 中间区间（26~28）保持上一状态，不会狂抖。

停程序：在 SSH 里按 Ctrl+C。

本步成功判据：能演示超温开 / 降温关，风扇真的跟着假温度转。

步骤 4：改阈值加深

打开 temperature_fan.c 顶部宏，把 T_HIGH / T_LOW 改成别的数（比如 27 / 25），重新 make 再跑，观察风扇开/关的温度点变了。

也可以把 STEP_DELTA 改大（温度变化更快），更容易看到开关切换。

目的：体会到「阈值是程序里的变量，硬件只需要跟着高低电平走」——这就是第三章的完整心智。

常见故障

现象先查什么
程序报 Permission denied用 sudo ./temperature_fan 跑
程序报 busy / 打不开 gpiochip有没有残留的 gpioset 占着 line 5？sudo pkill -x gpioset 后重试
程序在跑，风扇完全不动共地？继电器 5V？跳帽是否 H？NO/COM 是否接风扇红线？信号线是否真在 IO1_5？
继电器灯亮，风扇不转风扇 5V 回路：NO–COM–红线–黑线回 GND
某根脚怎么都拉不高（换根脚就好）这就是讲义「前沿板卡要运行时查证」：换一根可用脚，并记进实验记录
file 显示 x86-64交叉工具链没生效，检查 CROSS_COMPILE / PATH；或干脆板端原生编译

排查方法详见讲义「故障排查：信号链五环」——先软件后硬件，每环拿证据。
