# Lab 5：判断 ruyi device provision 的适用范围

## 对应讲次

| 项目 | 内容 |
| --- | --- |
| 章节 | 第一章 RISC-V 开发生态与环境准备 |
| 讲次 | Class 5 |
| 课程主题 | `ruyi device provision` 适用边界 |
| 实验类型 | 必做实验 |

## 实验目标

- 查询当前 `ruyi` 版本提供的 device/provision 能力。
- 根据精确设备标识判断课程目标板是否受支持。
- 在不冒险写入未知设备的前提下形成自动或手工流程决策。

## 对应知识点

| # | 知识点 | 本实验中的验证方式 |
| --- | --- | --- |
| 1 | provision 的目的 | 描述输入、动作和输出 |
| 2 | 版本差异 | 保存本机帮助输出 |
| 3 | 设备与变体 | 记录查询标识和结果 |
| 4 | 写入风险 | 完成六项风险清单 |
| 5 | 支持边界 | 给出支持、不支持或部分支持结论 |
| 6 | 结果验证 | 设计启动、系统和网络验收项 |

| 项目 | 要求 |

## 硬件连接或部署关系

| 模块 | 引脚/接口 | 连接说明 | 注意事项 |
| --- | --- | --- | --- |
| 主机 | 网络 | 查询软件源和设备信息 | 保存查询时间与版本 |

| 串口 | 调试接口 | provision 后验证启动 | 作为恢复和观察通道 |

## 实验任务

### 任务 1：检查命令能力

确认本机版本是否具有 device/provision 相关子命令。

### 任务 2：查询课程目标板支持

使用精确设备名称和变体查询，保存原始结果。

### 任务 3：完成风险评估与路径选择

选择自动 provision、部分使用工具能力或完全手工烧录，并说明理由。

## 实验步骤

1. 记录版本和帮助：

```bash
ruyi --version
ruyi device --help
ruyi device provision --help
```

2. 根据帮助执行设备列表或搜索命令，查询 LicheePi 4A 及对应变体。
3. 填写风险清单：

| 检查项 | 结论 | 依据 |
| --- | --- | --- |
| 设备是否明确列出 |  |  |
| 变体是否与实物一致 |  |  |
| 镜像是否匹配 |  |  |
| 写入目标是否唯一 |  |  |
| 数据是否已备份 |  |  |
| 是否具备恢复通道 |  |  |

4. 形成决策：

- 六项均明确且工具支持完整：可按帮助执行。
- 设备未列出或变体不明：停止自动写入，采用官方手工流程。
- 工具只支持查询或下载：只使用已确认的非写入能力。

5. 若课程要求并确认安全后执行 provision，保存全部日志；否则只提交决策记录，不为“完成实验”而强行写入。
6. 对实际执行结果使用以下命令验证：

```bash
cat /etc/os-release
uname -m
ip -br addr
```

## 验收记录

| 记录项 | 内容 |
| --- | --- |
| 运行命令 | 版本、帮助、设备查询和验证命令 |

## 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 没有 `device` 子命令 | 当前版本不支持或命令结构变化 | 保存版本和帮助，使用当前官方说明 |
| 搜不到设备 | 软件源未更新或设备未受支持 | 更新元数据后复查，仍无结果则走手工流程 |
| 设备名称相似 | 只按商品名判断 | 核对硬件版本、内存和存储变体 |
| 无法确认写入目标 | 多个存储设备同时连接 | 停止操作并断开无关设备 |
