## 实验目标

- 从课程指定的可信来源安装 `ruyi`。
- 查询并选择适用于 RISC-V Linux 用户态的工具链。
- 通过版本、目标三元组和 ELF 文件架构完成工具链验证。

## 对应知识点

| # | 知识点 | 本实验中的验证方式 |
| --- | --- | --- |
| 1 | `ruyi` 与编译器的区别 | 说明管理工具与编译工具职责 |
| 2 | 命令路径与版本 | 保存 `command -v` 和版本输出 |

| 6 | 二进制架构检查 | 使用 `file` 检查输出 |

## 实验任务

### 任务 1：安装并检查 `ruyi`

记录安装来源、安装路径和版本。

### 任务 2：查询并安装工具链

根据当前版本帮助查询候选工具链，说明选择理由。

### 任务 3：编译最小程序

编译只返回 0 的 C 程序，并检查生成文件架构。

## 实验步骤

1. 按课程指定的官方安装说明安装 `ruyi`。
2. 检查命令与帮助。

```bash
command -v ruyi
ruyi --version
ruyi --help
```

3. 根据帮助更新软件源并查询 RISC-V Linux 工具链。
4. 安装所选工具链，进入相应环境。
5. 检查编译器。

```bash
<compiler> --version
<compiler> -dumpmachine
```

6. 创建 `hello.c`：

```c
int main(void) {
    return 0;
}
```

7. 编译并检查：

```bash
<compiler> hello.c -o hello-riscv
file hello-riscv
```

## 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 找不到 `ruyi` | 安装目录不在 `PATH` | 核对安装路径并重新加载 shell |
| 查询包失败 | 网络、代理、时间或证书异常 | 保存错误，逐项检查连接和时间 |
| `file` 显示 x86-64 | 调用了主机 GCC | 用 `command -v` 与 `-dumpmachine` 复核 |
