4.1

串口是聊天线：字节怎么进出

字节怎么进出

串口是按约定速率、逐字节收发的双向通道。硬件上常叫 UART。对本课程序来说：你敲的字变成字节流进入进程；程序 printf 回去的字出现在同一窗口。

你（键盘） │ 敲 "status\n" ▼ SSH 终端 ──► 标准输入 stdin │ fgets() / read() ▼ 你的 C 程序（解析命令、做事） │ printf / write ▼ SSH 终端窗口里出现回复

第一章用串口登录系统；本章用同一类通道做应用层对话：程序读你的命令行，再打印状态。验收一律走 SSH 的 stdin/stdout——本课不要求再接一根物理串口线。

用 SSH 终端练读写

在 SSH 里跑程序：从 stdin 读一行、往 stdout 写回复。确认「打字 → 程序 → 回复」闭环。脚手架默认即此路径。

/* 读一行（到 '\\n' 或缓冲满） */
char line[128];
if (fgets(line, sizeof(line), stdin) == NULL)
    /* EOF 或错误 */ ;

printf("[INFO] got: %s", line);
本节成果：能画出「键盘 → stdin → 程序 → 终端回复」；知道本章命令入口是 SSH 窗口。
4.2

接传感器与命令表

DHT22：第一次接传感器

DHT22 是温湿度探头，模块上三根针：正（VCC）、负（GND）、OUT（数据线）。它内部一直在测，但你不问它不说——程序发开始信号后，它回传 40 位（湿度、温度、校验）。对程序来说，这是输入侧「读一个数」。

为何数据线要过 TXS

DHT22 数据线是 3.3 V 电平，板子 GPIO 是 1.8 V：

  1. 板子叫不醒它：GPIO 高只有 1.8 V，传感器认「高」要更高。
  2. 它回话会超压：传感器把线拉到 3.3 V，直接进 1.8 V 脚不安全。

TXS0108E 做双向电平转换：A 侧接板子 1.8 V，B 侧接传感器 3.3 V；同号 A1↔B1 是一对。AMS1117-1.8V 小板给 TXS 的 VA（低压侧电源）供电；VB 接 3.3 V；OE 拉高使能。

排针 IO1_6 (1.8V) ── A1 | TXS | B1 ── DHT22 OUT (3.3V) VA ← AMS 1.8V VB ← 3.3V 继电器 / 风扇：仍用第三章 IO1_5 直连

焊接步骤与逐针接线表在 lab.html——讲义到此把「为何」说清即可。

读取：单总线位带（脚手架已实现）

流程：IO1_6 配输出 → 拉低约 1.1 ms → 拉高 → 改输入 → 读 40 位 → 校验。用户态要稳，靠三件事：忙轮询分辨位宽、忽略过短毛刺、校验不过时换一种对齐再试。失败打 [ERR] 并重试；脚手架已写好，实验侧接对线。

命令表：字符串对应函数

命令表是「名字 → 处理函数」。收到一行后先拆出命令名，再查表调用。比一长串 if/else 清晰；后面加命令只多一行。

输入行："set temp 30" │ ▼ 拆词：cmd="set", args="temp 30" │ ▼ 查表 → cmd_set(...) │ ▼ 改温度 bar，打印确认
struct cmd_entry {
    const char *name;
    int (*handler)(char *args);
};

实验里你要自己写：cmd_status / cmd_set、表 g_cmds[]、以及负责拆词查表的 dispatch_command。

status 与 set

命令例子行为
statusstatus打印最近温度、湿度、风扇、两条 bar
set temp <数>set temp 30改温度 bar（高于开、低于关）
set humidity <数>set humidity 80改湿度 bar（同上）

命令只改内存里的阈值，下一轮采样决策立刻用上，不必重启进程。

本节成果：能说明为何要 TXS；能说出命令表与 status/set 语义；知道实现落在实验。
4.3

两边同时工作

一句话：有事叫我（你敲了字，或采样时间到了），没事就睡觉——别干等打字把风扇饿死，也别用固定 sleep 让命令迟迟不回。

为何「先读命令再采样」串成一条线不行

程序要同时做两件事：约每 2 秒采样并按阈值开/关风扇；随时响应你敲的 status / set。

错误一：阻塞在读命令上。没人打字时进程卡在 fgets，采样永不执行，风扇停在上次状态。

错误二：固定 sleep(2) 再瞥一眼命令。风扇节奏对了，但敲完字最多要等满整个 sleep 才有回复。

目标： 风扇仍按温湿度自动开/关 同时 敲 status / set 立刻有回复

正确机制：select

select 就是把上面那句话交给内核：盯着 stdin；再设一个超时。谁先到谁叫醒你。

select 返回含义本课该做什么
< 0出错（含被信号打断）perror；按策略退出或重试
0超时（该采样了）调用 sample_and_control
> 0有字可读读一行并派发命令
/* 伪代码：方向示意；完整实现在实验由你写 */
for (;;) {
    准备 rfds（cmd_fd）与超时;
    n = select(...);
    if (n == 0) sample_and_control();
    else if (FD_ISSET(cmd_fd, &rfds)) read_command_line();
}

写主循环时注意：处理完命令不要把采样时钟重新拨成满 2 秒。超时要用「距下次采样还剩多久」，否则风扇节奏会被打字打乱。时间轴示意：

t=0.0 采样，下次该在 t=2.0 t=0.0 select(还剩 ≈2s) t=0.7 敲 status → 立刻回复 再 select(还剩 ≈1.3s) ← 不重置成 2s t=2.0 超时 → 再采样

温湿度怎么一起控风扇

DHT22 同时给出温度和湿度。脚手架里是两条单阈值 bar：

  • 开：温度高于温度 bar，或 湿度高于湿度 bar
  • 关：温度低于温度 bar，并且 湿度低于湿度 bar

模拟模式（默认）里湿度大致恒定，主要靠模拟温度演示；接真传感器后可哈气观察湿度支路。命令 set temp / set humidity 分别改两条 bar。
