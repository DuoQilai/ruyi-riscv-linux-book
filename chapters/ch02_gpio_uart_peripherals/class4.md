# 2.4 PWM/ADC/I2C/SPI 与综合传感器

## 对应大纲

大纲讲次原文：第4讲 PWM/ADC/I2C/SPI 与综合传感器。
大纲知识点原文：PWM 输出控制；ADC 模拟量采集；I2C 总线与设备扫描；OLED 显示屏驱动（SSD1306）；DHT22 温湿度传感器；温控风扇综合控制。

PWM 输出控制、ADC 模拟量采集、I2C 总线与设备扫描、OLED SSD1306、DHT22、温控风扇综合控制。

## 目标

学生能整合双温度传感器、OLED/串口显示和风扇控制，形成章末阶段项目。

## 知识点

| # | 知识点 | 本讲说明 |
| --- | --- | --- |
| 1 | PWM 输出控制 | 使用 `/sys/class/pwm` 配置 period、duty_cycle、enable，理解风扇调速 |
| 2 | ADC 模拟量采集 | 认识 IIO 子系统，读取光敏/电位器并换算电压 |
| 3 | I2C 总线与设备扫描 | 使用 `i2cdetect` 查找 OLED 地址，理解 I2C 总线和设备地址 |
| 4 | OLED 显示屏驱动 | SSD1306 初始化、显存映射、ASCII 文本显示和状态页面 |
| 5 | DHT22 温湿度传感器 | 单总线时序、校验、多传感器编号和数据结构 |
| 6 | 温控风扇综合控制 | DHT22 x2、阈值、回差、异常读数保护、继电器/MOSFET 控制风扇 |

## 讲授要点

- PWM、ADC、I2C、SPI 先建立接口认知，细节放实验和后续项目迭代，不在大纲外新增小节。
- DHT22 对时序敏感，用户态读取可能受调度影响；课堂应强调重试、校验和异常保护。
- 风扇不能直接由 GPIO 供电，必须使用继电器模块或 MOSFET 驱动，并让外部电源与控制侧共地。
- 温控逻辑必须有回差：例如高于 30.0 摄氏度启动，低于 28.0 摄氏度停止，避免频繁抖动。
- OLED 和串口显示同一份状态：两路温度、阈值、风扇状态、异常计数和最近更新时间。

## 操作或演示

```bash
sudo apt install -y i2c-tools
i2cdetect -l
sudo i2cdetect -y <bus>
ls /sys/class/pwm
ls /sys/bus/iio/devices
```

项目配置示例：

```text
DHT22_A_GPIO=<line-a>
DHT22_B_GPIO=<line-b>
FAN_GPIO=<fan-line>
THRESHOLD_ON_C=30.0
HYSTERESIS_C=2.0
MAX_VALID_C=60.0
MIN_VALID_C=-10.0
```

控制逻辑：两路 DHT22 任一路有效温度达到启动阈值则启动风扇；所有有效温度都低于 `THRESHOLD_ON_C - HYSTERESIS_C` 才停止；连续异常读数达到阈值时保持当前风扇状态或进入预设安全状态，并在 OLED/串口显示 `SENSOR_ERR`。

## 运行验证

| 验证项 | 命令或操作 | 预期现象 |
| --- | --- | --- |
| I2C 扫描 | `i2cdetect -y <bus>` | 能看到 SSD1306 常见地址，如 `0x3c` |
| DHT22 读取 | 运行采集程序 | 两路温湿度读数在合理范围且校验通过 |
| 风扇控制 | 模拟温度越过阈值 | 风扇启动，状态显示为 `ON` |
| 回差停止 | 温度低于停止阈值 | 风扇停止，状态显示为 `OFF` |
| 异常保护 | 断开一路 DHT22 或制造无效读数 | 不因单次异常误触发，显示异常计数 |

## 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| OLED 扫描不到 | I2C 总线号错误、SDA/SCL 接反、未供电 | 换总线扫描，断电检查接线 |
| DHT22 读数偶发失败 | 用户态时序抖动或线太长 | 增加重试、缩短线长、记录失败率 |
| 风扇不转 | 供电不足、驱动接线错误、继电器逻辑反 | 单独测试驱动模块和风扇电源 |
| 风扇频繁启停 | 没有回差或阈值太接近环境温度 | 设置 1 到 3 摄氏度回差 |
| GPIO 发热或损坏风险 | 直接用 GPIO 带风扇 | 立即断电，改用继电器或 MOSFET 驱动 |
