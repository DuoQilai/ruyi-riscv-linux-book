# 5.3 常用算法向量化优化

## 对应大纲

大纲讲次原文：第3讲 常用算法向量化优化。
大纲知识点原文：向量化 memcpy/memset；向量化矩阵乘法；向量化卷积运算；向量化激活函数；向量化图像处理；定点量化推理加速。

向量化 memcpy/memset、向量化矩阵乘法、向量化卷积运算、向量化激活函数、向量化图像处理、定点量化推理加速。

## 目标

学生能把数据并行算法拆成可向量化的内层循环，重点完成 RVV SGEMM 或图像处理算子的标量/RVV 对照实现。

| # | 知识点 | 内容 |

| 1 | 向量化 memcpy/memset | 对齐、尾量、大块/小块路径和内存带宽限制。 |

## 讲授要点

- 判断算法是否适合向量化时，先看内层循环是否存在独立、连续、同类型的数据操作。
- SGEMM 的优化核心不是“把所有循环都向量化”，而是让内层乘加、数据布局和缓存复用配合。
- 图像算法往往受访存影响，必须同时记录数据大小和输入格式。
- int8 推理要重视溢出和累加宽度，正确性验证不能只看程序是否运行。
- 本讲不追求完整工业级 BLAS，重点是让学生理解从 naive 到 tiled/RVV 的改进路径。

## 操作或演示

1. 建立 SGEMM 基准接口：

```c
void sgemm_scalar(int m, int n, int k, const float *A, const float *B, float *C);
void sgemm_rvv(int m, int n, int k, const float *A, const float *B, float *C);
```

2. 使用小规模矩阵验证正确性：

```bash
./bench_sgemm --m 16 --n 16 --k 16 --check
```

3. 使用多组规模记录耗时：

```bash
for s in 64 128 256; do
  ./bench_sgemm --m $s --n $s --k $s --repeat 5
done
```

4. 计算吞吐量：

```text
GFLOPS = 2 * M * N * K / seconds / 1e9
speedup = scalar_seconds / rvv_seconds
```

## 运行验证

| 验证项 | 命令或方法 | 预期现象 |
| --- | --- | --- |
| 小矩阵正确性 | `./bench_sgemm --m 8 --n 8 --k 8 --check` | 最大误差小于设定阈值。 |
| 中等规模耗时 | `./bench_sgemm --m 128 --n 128 --k 128 --repeat 5` | 输出 scalar/RVV 秒数。 |
| 吞吐量 | 根据耗时计算 GFLOPS | 表格包含 M/N/K、耗时、GFLOPS、加速比。 |
| 算法解释 | 画出循环顺序和数据访问方向 | 能指出瓶颈是计算还是访存。 |

## 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| SGEMM 结果误差较大 | 浮点累加顺序不同 | 使用 `max_abs_error` 和 `max_rel_error` 双指标。 |
| 加速比随规模变化反常 | cache 命中率或内存带宽变化 | 分别测试 64/128/256/512 并解释趋势。 |
| int8 结果溢出 | 使用了过窄累加类型 | 中间累加使用 `int32_t`。 |

## 本讲成果

- 一个 SGEMM 或图像算子的标量/RVV 对比实现。
- 一张包含不同数据规模的性能表。
- 对至少一个瓶颈的文字分析，例如访存、对齐、尾量或缓存复用不足。
