## 实验目标

- 正确识别课程中的 ISA、SoC、开发板、操作系统和开发工具。
- 识别 LicheePi 4A 的关键接口并记录连接用途。
- 建立可执行的个人软硬件准备清单。
- 从课程指定的可信来源安装 `ruyi`。
- 查询并选择适用于 RISC-V Linux 用户态的工具链。
- 通过版本、目标三元组和 ELF 文件架构完成工具链验证。

## 实验任务

### 任务 1：完成平台分层

将 RISC-V、TH1520、LicheePi 4A、RevyOS、`ruyi` 和课程应用放入正确层次。

### 任务 2：标注开发板接口并建立环境清单

拍摄或使用课程提供的板卡图片，标注供电、数据、串口、网络、启动介质和扩展接口。汇总"已有、缺少、待确认"三类项目，给出补齐计划。

### 任务 3：安装并检查 `ruyi`

记录安装来源、安装路径和版本。

### 任务 4：查询并安装工具链

根据当前版本帮助查询候选工具链，说明选择理由。

### 任务 5：编译最小程序并验证架构

编译只返回 0 的 C 程序，检查生成文件架构。

## 实验步骤

### 第一部分：平台与环境

1. 记录主机系统和架构。

```bash
uname -a
uname -m
```

2. 填写平台分层表，不允许把软件、硬件和 ISA 写在同一层。
3. 对照板卡资料完成接口标注。
4. 检查 USB 线是否标明数据能力，检查 USB-TTL 模块逻辑电平。
5. 汇总"已有、缺少、待确认"三类项目，给出补齐计划。

### 第二部分：ruyi 与工具链

6. 按课程指定的官方安装说明安装 `ruyi`。
7. 检查命令与帮助。

```bash
command -v ruyi
ruyi --version
ruyi --help
```

8. 根据帮助更新软件源并查询 RISC-V Linux 工具链。
9. 安装所选工具链，进入相应环境。
10. 检查编译器。

```bash
<compiler> --version
<compiler> -dumpmachine
```

11. 创建 `hello.c`：

```c
int main(void) {
    return 0;
}
```

12. 编译并检查：

```bash
<compiler> hello.c -o hello-riscv
file hello-riscv
```

## 常见问题

| 现象 | 可能原因 | 处理方式 |
| --- | --- | --- |
| 无法确认板卡版本 | 只看商品页面，未看实物丝印 | 拍摄板卡正反面并核对官方资料 |
| USB-TTL 标注不清 | 模块资料缺失 | 暂不接板，先确认逻辑电平 |
| 主机不是 Linux | 使用 macOS 或 Windows | 记录差异，准备课程支持的 Linux 环境 |
| 找不到 `ruyi` | 安装目录不在 `PATH` | 核对安装路径并重新加载 shell |
| 查询包失败 | 网络、代理、时间或证书异常 | 保存错误，逐项检查连接和时间 |
| `file` 显示 x86-64 | 调用了主机 GCC | 用 `command -v` 与 `-dumpmachine` 复核 |
