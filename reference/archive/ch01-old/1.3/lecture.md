# 1.3 ruyi device provision 适用边界

## 本讲目标

- 能解释 device provision 的目的、输入、输出和潜在风险。
- 能使用当前 `ruyi` 版本查询设备支持信息，而不是凭板卡名称猜测。
- 能对比手工烧录流程（1.2）与自动化 provision 的适用场景与风险差异。
- 能根据设备、镜像、连接方式和数据风险选择自动 provision 或手工准备流程。

## 前置条件

- 已安装并验证 `ruyi`。
- 已完成至少一次 RevyOS 手工烧录和首次启动（实验 1.2）。
- 已保存重要数据，并能识别课程目标板和存储介质。

## 知识简介

### provision 是什么

Device provision 是把设备准备成可使用状态的自动化过程，可能包括下载镜像、选择设备变体、写入存储介质或生成操作指引。它的价值是减少重复步骤，但只有在工具明确支持设备、镜像和连接方式时才可靠。自动化不会消除误选磁盘、断电或版本不匹配的风险，因此"能否运行命令"不等于"适合运行命令"。

### 手工流程 vs 自动化 provision

实验 1.2 中的手工流程每一步都在学习者控制之下：手动下载镜像、手动校验、手动确认目标设备、手动执行烧录、手动验证启动。这是最可控、最可调试的方式，但重复次数多时效率低。provision 将多个步骤封装为自动化流程，效率高但需要严格的前置条件确认——工具是否支持该设备？变体是否匹配？写入目标是否正确？

表 1-1：手工流程与 provision 对比

| 维度 | 手工流程（1.2） | 自动化 provision |
| --- | --- | --- |
| 控制粒度 | 每步可控，可随时停止 | 流程封装，中断后需恢复 |
| 适用条件 | 只要有镜像和烧录工具即可 | 设备必须在软件源中明确列出 |
| 误操作风险 | 人为确认每一步，可发现异常 | 自动化写入可能跳过确认 |
| 可调试性 | 高，每步可单独验证 | 低，失败后需拆解自动化步骤 |
| 重复效率 | 低，需重复执行相同命令 | 高，一条命令完成多步 |
| 建议场景 | 首次使用、设备未列出、数据风险高 | 设备明确支持、重复部署、空白介质 |

## 环境准备

| 项目 | 要求 | 检查方式 |
| --- | --- | --- |
| `ruyi` | 已安装且软件源可查询 | `ruyi --version` |
| 设备资料 | 型号、硬件版本、存储方式明确 | 核对丝印和说明 |
| 数据保护 | 重要数据已备份 | 检查备份文件 |
| 连接 | 使用工具要求的 USB、串口或存储设备连接 | 查看当前帮助 |
| 电源 | provision 期间稳定供电 | 核对电源规格 |

## 操作步骤

### 步骤 1：读取当前版本帮助

```bash
ruyi device --help
ruyi device provision --help
```

若当前版本没有这些子命令，记录版本与帮助输出，不自行拼凑参数。这本身就是"当前版本不具备该路径"的有效结论。

### 步骤 2：查询设备与变体

使用帮助中提供的列表或查询命令，记录设备标识、变体、支持的镜像和 provision 方式。板卡商品名相同但硬件版本、内存或存储配置不同，也可能需要不同变体。

### 步骤 3：执行风险检查

在运行任何写入操作前逐项回答：

1. 设备是否在当前软件源中明确列出？
2. 变体是否与实物一致？
3. 写入目标是否唯一且可确认？
4. 重要数据是否已备份？
5. 供电和数据连接是否稳定？
6. 是否已准备串口或其他恢复通道？

任一项不能确认，都应停止自动 provision。

### 步骤 4：选择操作路径

- **明确支持**：按当前帮助逐步执行，保留下载、选择和写入日志。
- **未明确支持**：使用 1.2 中的手工烧录流程，记录"该设备在 ruyi 版本 X 中未列出"。
- **仅部分支持**：只使用已确认安全的查询、下载或生成指引能力，不执行未知写入步骤。

### 步骤 5：完成后验证

若执行了 provision，验证项目包括设备能启动、系统版本正确、架构正确、网络可用，并记录是否需要额外手工配置。

```bash
cat /etc/os-release
uname -m
ip -br addr
```

## 课堂练习

给出三个场景并作决策，说明选择自动或手工流程的理由：

1. 设备完全匹配且有重要数据。
2. 设备未列出但名称相似。
3. 设备列出且为新空白存储。

## 运行验证

| 验证项 | 预期现象 | 记录 |
| --- | --- | --- |
| 帮助检查 | 能确认当前版本是否提供 provision | 保存输出 |
| 设备查询 | 能得到明确支持信息或明确"不支持"结论 | 记录依据 |
| 风险清单 | 六项均有答案 | 提交清单 |
| 路径选择 | 自动或手工流程理由清楚，且与手工流程（1.2）对比明确 | 提交决策记录 |
| 结果验证 | 若执行写入，系统能启动并通过基础检查；若未执行，记录替代方案 | 保存输出 |

## 常见问题

### 把相似设备当成同一设备

商品名、SoC 或外观相似不能证明镜像和写入流程兼容。必须使用工具或官方资料中的精确标识。

### 未确认写入目标

自动化写入仍可能覆盖错误存储设备。目标不唯一时应断开无关设备或改用 1.2 的手工流程。

### 帮助示例与本机版本不同

以本机 `--help` 和当前软件源为准，记录版本差异，不盲目尝试旧参数。

### 为"完成实验"强行执行 provision

课程不要求在不安全条件下执行自动写入。提交"当前版本不支持该设备型号 X"并描述手工替代流程，同样是有效的实验结论。
